# GitHub Project Workflow

## Pull Requests

- All PRs must have a descriptive title and reference the related issue (e.g., `Closes #123`).
- Use the standard PR template if available.
- Highlight breaking changes or database migrations required.

## Issue Management

- Label issues appropriately (`bug`, `enhancement`, `documentation`).
- Provide clear steps to reproduce for bugs.
- For new features, include user stories and acceptance criteria.
