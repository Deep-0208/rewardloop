# 1. Sprint Goal

Build the complete customer selection workflow for the Add Visit flow.

After this sprint, a salon owner or staff member can:

- Tap "Add Visit" from the Dashboard.
- Enter a phone number.
- Instantly find an existing customer.
- Or automatically create a new customer inline.
- Continue to Catalog selection.

The entire customer selection process must complete in **under 10 seconds**.

---

## Business Context

From `00_Founder_Decisions.md` — Decision 06 (Customer Management):

- Customer identity is always based on **Phone Number**.
- Phone required.
- Name optional.
- Auto create customer if not found.
- No customer creation screen (creation happens inline).

From `00_Founder_Decisions.md` — Decision 08 (Visit Flow):

- Dashboard → + → Phone Number → Search Customer → Customer Found? → Services → Rewards → Payment → Complete → Dashboard.
- Single vertical flow.
- Minimal typing.
- Auto search.
- Auto customer creation.

From `00_Founder_Decisions.md` — Decision 25 (Success Metrics):

- Billing Time ≤ 12 seconds (complete visit).
- Customer selection is the first step — it must be fast.

From `09_UI_UX_Specification.md`:

- Add Visit Flow: Phone → Customer → Catalog → Reward → Payment → Complete.
- If customer not found: Show Name field → Auto create customer.

# 4. Pages

## 4.1 Customer Selection Page

**Purpose:** The first step of Add Visit. Identify or create the customer for the billing session.

**Route:** `/(app)/visit`

**Template:** Standard Workflow (Header → Content → Sticky CTA)

**Components:**

- AppBar (Back button, title: "Add Visit")
- CustomerSearchInput (phone number)
- RecentCustomerList (shown before search)
- CustomerCard (shown when customer found)
- CreateCustomerForm (shown when customer not found — name field)
- SearchLoader (inline searching indicator)

- ErrorBanner (error state)

**Navigation:**

- Back → `/(app)/dashboard`
- Continue → `/(app)/visit` (step = 'catalog', controlled by `useBillingStore`) (Sprint 4.2)

**Primary Action:** Continue (select customer and proceed to catalog).

**Validation:**

- Phone number: required, 10 digits, numeric only.
- Customer name (new customer): optional, 2–50 characters if provided, trimmed.

**Loading:**

- SearchLoader appears inline while searching.
- ContinueButton shows spinner during customer creation.

**Errors:**

- Invalid phone → inline error: "Enter a valid 10-digit phone number."
- Network error → toast: "Unable to search. Please check your connection."
- Server error → toast: "Something went wrong. Please try again."
- Customer creation failed → toast: "Unable to create customer. Please try again."

# 6. Database

## Tables Touched

### 6.1 `customers`

**Reads:**

- Search by `business_id` + `phone` (exact match).
- Recent customers by `business_id` ordered by `last_visit_at DESC`, limit 5.
- Return: `id`, `name`, `phone`, `total_visits`, `last_visit_at`.

**Writes:**

- Create new customer record when phone not found.
- Fields set: `business_id`, `phone`, `name` (optional), `total_visits` (0), `created_at`.

**Updates:**

- None during customer selection (visit count updated in Sprint 4.3).

**Relationships:**

- `customers.business_id` → `businesses.id`
- Unique constraint: `business_id` + `phone` (from `06_Database_Design.md`).

**Indexes Used:**

- `business_id + phone` composite index (exact search).
- `business_id + last_visit_at` (recent customers query).

---

### 6.2 `reward_wallets`

**Reads:**

- Fetch current reward balance for the found customer.
- Join `reward_wallets.customer_id` = `customers.id`.

**Writes:**

- Create reward wallet for new customer (balance 0).

**Updates:**

- None during customer selection.

**Relationships:**

- `reward_wallets.customer_id` → `customers.id`

---

### 6.3 `transactions`

**Reads:**

- None directly during customer selection.
- Recent customers are derived from `customers.last_visit_at`, not from the transactions table.

**Writes:**

- None during customer selection.

# 7. Server Actions

## 7.1 `searchCustomer()`

**Purpose:** Search for an existing customer by phone number within the current business.

**Input:**

```typescript
{
  phone: string; // 10-digit phone number
}
```

**Validation:**

1. User must be authenticated.
2. User must have a business.
3. Phone must be exactly 10 digits, numeric only.

**Database:**

- Query `customers` where `business_id` = current business AND `phone` = input phone.
- If found, join `reward_wallets` to get `current_balance`.

**Output (Success — Found):**

```typescript
{
  success: true,
  data: {
    found: true,
    customer: {
      id: string,
      name: string | null,
      phone: string,
      totalVisits: number,
      lastVisitAt: string | null,
      rewardBalance: number
    }
  }
}
```

**Output (Success — Not Found):**

```typescript
{
  success: true,
  data: {
    found: false,
    customer: null
  }
}
```

**Output (Failure):**

```typescript
{
  success: false,
  code: "VALIDATION_FAILED" | "AUTH_REQUIRED" | "SERVER_ERROR",
  message: string
}
```

**Errors:**

| Error             | Code              | User Message                           |
| ----------------- | ----------------- | -------------------------------------- |
| Invalid phone     | VALIDATION_FAILED | "Enter a valid 10-digit phone number." |
| Not authenticated | AUTH_REQUIRED     | Redirect to login.                     |
| Database error    | SERVER_ERROR      | "Unable to search. Please try again."  |

**Caching:**

- TanStack Query key: `['customer', 'search', phone]`
- Stale time: 0 (always fresh — customer data changes frequently).
- Enabled only when phone is exactly 10 digits.

---

## 7.2 `createCustomer()`

**Purpose:** Create a new customer for the business when the phone number is not found.

**Input:**

```typescript
{
  phone: string,        // 10-digit phone number
  name?: string         // optional, 2–50 chars if provided
}
```

**Validation:**

1. User must be authenticated.
2. User must have a business.
3. Phone must be exactly 10 digits, numeric only.
4. Customer must not already exist for this business + phone (prevent race condition duplicates).
5. Name (if provided): 2–50 characters, trimmed.

**Database:**

- Insert into `customers`: `business_id`, `phone`, `name`, `total_visits` (0), `created_at`.
- Insert into `reward_wallets`: `customer_id`, `current_balance` (0), `created_at`.

**Output (Success):**

```typescript
{
  success: true,
  data: {
    customer: {
      id: string,
      name: string | null,
      phone: string,
      totalVisits: 0,
      lastVisitAt: null,
      rewardBalance: 0
    }
  }
}
```

**Output (Failure):**

```typescript
{
  success: false,
  code: "VALIDATION_FAILED" | "DUPLICATE_CUSTOMER" | "AUTH_REQUIRED" | "SERVER_ERROR",
  message: string
}
```

**Errors:**

| Error             | Code               | User Message                                   |
| ----------------- | ------------------ | ---------------------------------------------- |
| Invalid phone     | VALIDATION_FAILED  | "Enter a valid 10-digit phone number."         |
| Duplicate phone   | DUPLICATE_CUSTOMER | "This customer already exists."                |
| Invalid name      | VALIDATION_FAILED  | "Name must be 2–50 characters."                |
| Not authenticated | AUTH_REQUIRED      | Redirect to login.                             |
| Database error    | SERVER_ERROR       | "Unable to create customer. Please try again." |

**Caching:**

- Invalidate `['customer', 'search', phone]` after creation.
- Invalidate `['customer', 'recent']` after creation.

---

## 7.3 `getRecentCustomers()`

**Purpose:** Fetch the most recently served customers for quick selection.

**Input:**

```typescript
{
  limit: number; // default: 5
}
```

**Validation:**

1. User must be authenticated.
2. User must have a business.
3. Limit: 1–10.

**Database:**

- Query `customers` where `business_id` = current business AND `last_visit_at` IS NOT NULL.
- Order by `last_visit_at DESC`.
- Limit to N records.

**Output (Success):**

```typescript
{
  success: true,
  data: {
    customers: Array<{
      id: string,
      name: string | null,
      phone: string,
      totalVisits: number,
      lastVisitAt: string
    }>
  }
}
```

**Output (Failure):**

```typescript
{
  success: false,
  code: "AUTH_REQUIRED" | "SERVER_ERROR",
  message: string
}
```

**Errors:**

| Error             | Code          | User Message                       |
| ----------------- | ------------- | ---------------------------------- |
| Not authenticated | AUTH_REQUIRED | Redirect to login.                 |
| Database error    | SERVER_ERROR  | "Unable to load recent customers." |

**Caching:**

- TanStack Query key: `['customer', 'recent']`
- Stale time: 60 seconds.
- Refetch on mount: yes.
- Invalidated after creating a new customer or completing a visit.

# 8. Validation

## 8.1 Phone Number

| Rule              | Constraint                                       |
| ----------------- | ------------------------------------------------ |
| Required          | Yes                                              |
| Format            | Numeric only                                     |
| Length            | Exactly 10 digits                                |
| Country code      | "+91" prefixed server-side (not entered by user) |
| Client validation | Disable Continue until 10 digits                 |
| Server validation | Zod schema in every Server Action                |

**Zod Schema:**

```typescript
export const customerSearchSchema = z.object({
  phone: z
    .string()
    .length(10, "Phone number must be 10 digits")
    .regex(/^\d{10}$/, "Enter a valid 10-digit phone number"),
});
```

---

## 8.2 Customer Name

| Rule               | Constraint                     |
| ------------------ | ------------------------------ |
| Required           | No (optional)                  |
| Minimum length     | 2 characters (if provided)     |
| Maximum length     | 50 characters                  |
| Trimmed            | Yes                            |
| Allowed characters | Letters, spaces, dots, hyphens |
| Client validation  | On blur                        |
| Server validation  | Zod schema                     |

**Zod Schema:**

```typescript
export const createCustomerSchema = z.object({
  phone: z.string().regex(/^\d{10}$/),
  name: z
    .string()
    .min(2, "Name must be at least 2 characters")
    .max(50, "Name must be 50 characters or less")
    .transform((val) => val.trim())
    .optional()
    .or(z.literal("")),
});
```

---

## 8.3 Duplicate Prevention

| Rule              | Constraint                                                   |
| ----------------- | ------------------------------------------------------------ |
| Unique constraint | `business_id` + `phone` (from `06_Database_Design.md`)       |
| Client-side       | Search result shows existing customer — no duplicate attempt |
| Server-side       | `createCustomer()` checks before insert                      |
| Race condition    | Database unique constraint catches concurrent inserts        |

# 9. Security

- **Business isolation.** All queries scoped to `business_id`. RLS enforced.
- **Server validation.** All inputs validated with Zod server-side.
- **Ownership validation.** Only users belonging to the business can search or create customers.
- **Never trust client.** Phone numbers and names validated server-side before any database operation.
- **Prevent enumeration.** Search only returns customers within the authenticated business. No cross-business leakage.
- **Rate limiting.** Not critical for customer search (authenticated, low-volume), but standard protections apply.

# 11. Search Behaviour

## 11.1 Debounce

- Search is debounced by **300ms** after the last keystroke.
- No search fires while the user is actively typing.
- Search triggers only when the debounce timer expires.

## 11.2 Auto Search

- Search triggers automatically — the user does not need to tap a search button.
- Search fires when the phone input reaches exactly 10 digits.
- Search also fires on debounce for partial inputs (but the server rejects inputs < 10 digits, so effectively only 10-digit inputs produce results).

## 11.3 Search Trigger

- Typing the 10th digit → debounced search fires.
- Pasting a 10-digit number → search fires immediately after debounce.
- Selecting a recent customer → phone input fills → search fires.

## 11.4 Keyboard Behaviour

- Numeric keyboard opens on focus (`inputMode="numeric"`).
- Keyboard stays open during search.
- Keyboard closes when the user taps outside or taps Continue.

## 11.5 Clear Search

- Tapping the clear (X) button clears the phone input.
- Clears the search result.
- Shows recent customers list again.
- Resets any new customer name input.

## 11.6 Paste

- Pasting a full 10-digit number fills the input.
- Non-numeric characters are stripped.
- If pasted value exceeds 10 digits, only the first 10 are used.
- Search triggers after paste.

## 11.7 Auto Focus

- Phone input auto focuses on page mount.
- Keyboard opens automatically.

## 11.8 Search Result Priority

1. Exact phone match within the business → show CustomerCard.
2. No match → show CreateCustomerForm.
3. Search in progress → show SearchLoader.
4. No input → show RecentCustomerList.

# 14. State Machine

```text
Idle (No Input)
    │
    ├── Recent Customers Loaded → Show Recent List
    │
    └── No Recent Customers → Show Empty Search
              │
              ▼
Typing (User Enters Digits)
    │
    ├── < 10 digits → Continue Disabled, Hide Recents
    │
    └── 10 digits → Debounce Timer Start
                        │
                        ▼
                  Searching
                        │
                        ├── Found → Show CustomerCard
                        │              │
                        │              └── Continue Enabled
                        │
                        └── Not Found → Show CreateCustomerForm
                                           │
                                           └── Continue Enabled
                                                    │
                                                    ▼
                                              Continue Tapped
                                                    │
                                                    ├── Existing Customer → Navigate (no server call)
                                                    │
                                                    └── New Customer → Creating
                                                                         │
                                                                         ├── Success → Navigate
                                                                         │
                                                                         └── Failure → Show Error, Stay
```

**Failure Transitions:**

- Searching → Network Error → Show Toast (State: Idle with digits)
- Searching → Server Error → Show Toast (State: Idle with digits)
- Creating → Duplicate → Show Toast, search again (State: Searching)
- Creating → Server Error → Show Toast (State: Not Found, retry)
- Any State → Session Expired → Redirect to Login

# 15. Error States

## 15.1 Invalid Phone Number

**User Message:** "Enter a valid 10-digit phone number."

**Display:** Inline error below phone input.

**Recovery:** User corrects the phone number.

## 15.2 Network Error (Search)

**User Message:** "Unable to search. Please check your connection."

**Display:** Toast notification.

**Recovery:** User retries by modifying input or waiting for connection.

## 15.3 Server Error (Search)

**User Message:** "Something went wrong. Please try again."

**Display:** Toast notification.

**Recovery:** User clears and re-enters the phone number.

## 15.4 Network Error (Creation)

**User Message:** "Unable to create customer. Please check your connection."

**Display:** Toast notification.

**Recovery:** User taps Continue again.

## 15.5 Server Error (Creation)

**User Message:** "Unable to create customer. Please try again."

**Display:** Toast notification.

**Recovery:** User taps Continue again.

## 15.6 Unauthorized / Session Expired

**User Message:** None (silent redirect).

**Recovery:** Redirect to login.

## 15.7 Duplicate Customer

**User Message:** "This customer already exists."

**Display:** Toast notification.

**Recovery:** Re-trigger search. The existing customer should now appear. This handles race conditions where two devices create the same customer simultaneously.

**Condition:** Business has no customers with `last_visit_at` (brand new business after onboarding).

**Icon:** Lucide `UserPlus`.

## 17.3 First Customer

**Condition:** Same as "No Recent Customers." The first time the owner searches for a phone number and creates a customer, it flows naturally through the "Not Found → Create" path.

# 18. Edge Cases

## 18.1 Paste Phone Number

- Full 10-digit paste fills the input.
- Non-numeric characters stripped.
- Search triggers after debounce.

## 18.2 Double Tap Continue

- Button disabled immediately on first tap.
- `isSubmitting` prevents duplicate creates.

## 18.3 Slow Search

- SearchLoader stays visible until response.
- Continue button remains disabled during search.

## 18.4 Offline

- Show toast: "You are offline."
- Disable Continue.
- Disable search (no server call possible).
- Recent customers may show from cache.

## 18.5 Page Refresh

- Customer selection resets to clean state.
- No data to restore (selection has not been persisted yet).
- Recent customers re-fetched.

## 18.6 Session Expired

- Server Action returns `AUTH_REQUIRED`.
- Redirect to login.

## 18.7 Duplicate Phone (Race Condition)

- Two devices create the same customer simultaneously.
- Database unique constraint prevents duplicate.
- `createCustomer()` catches the constraint error.
- Returns `DUPLICATE_CUSTOMER` code.
- Client re-triggers search to show the existing customer.

## 18.8 Keyboard Open

- Sticky CTA positions above the keyboard.
- Content scrolls to keep active input visible.
- No content hidden behind the keyboard.

## 18.9 Search While Typing

- Previous search requests are cancelled (TanStack Query handles via key change).
- Only the latest debounced search executes.
- No stale results displayed.

## 18.10 Large Customer Database

- Search is an exact phone match (not a fuzzy search), so performance is O(1) with the composite index.
- Recent customers limited to 5.
- No pagination needed.
